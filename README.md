# 🛡️ Spam Scanner — Email Spam Classifier

A spam email classifier and web app built in Python + Flask. Detects spam vs. legitimate ("ham") emails using **TF-IDF** text features with two classic classification techniques:

- **Multinomial Naive Bayes** — the traditional baseline for text classification, fast and effective
- **Linear SVM** (`LinearSVC`, calibrated for probabilities) — usually edges out Naive Bayes on accuracy for this kind of task

Paste any email into the web UI and get an instant verdict, a confidence score for both models, and the specific words that pushed the message toward "spam."

---

## Why these two techniques?

| Model | Strength | Weakness |
|---|---|---|
| **Naive Bayes** | Extremely fast to train and predict, works well even with limited data, easy to interpret via word probabilities. | Assumes words are independent of each other, which isn't really true — can be less accurate than SVM on nuanced text. |
| **Linear SVM** | Finds the best possible separating boundary between spam/ham in TF-IDF space, typically higher accuracy on text. | Slightly slower to train, and raw SVM scores need calibration to become readable probabilities (handled here via `CalibratedClassifierCV`). |

## Run it locally

```bash
git clone https://github.com/<your-username>/spam-classifier.git
cd spam-classifier

pip install -r requirements.txt
python app.py
```

Then open **http://127.0.0.1:5000**. The first run trains automatically if `model/*.pkl` don't exist yet (takes a couple of seconds); after that, `app.py` just loads the saved models.

Paste any message into the scanner, pick **Naive Bayes** or **SVM**, and hit **Scan message** to see:
- The verdict (SPAM / NOT SPAM)
- A probability bar for both classes
- Which words in your message are strongly associated with spam in the training data

The bottom of the page also shows each model's accuracy/precision/recall/F1 on a held-out test split.

### Retraining manually

```bash
python src/generate_data.py   # regenerate data/emails.csv
python src/train.py           # retrain both models on it, overwrite model/*.pkl
```

### Deploying it for free

Standard Flask app — works as-is on:
- **Render / Railway** — start command `gunicorn app:app` (add `gunicorn` to `requirements.txt`), `PORT` is picked up automatically.
- **PythonAnywhere** — point a WSGI app at `app.py`'s `app` object.
- **Docker** — `pip install -r requirements.txt && python app.py`.

## Use it as a JSON API

| Endpoint | Description |
|---|---|
| `GET /api/metrics` | Accuracy/precision/recall/F1 for both models on the test split |
| `POST /api/classify` | Body: `{"text": "...", "model": "naive_bayes" \| "svm"}` → verdict, probabilities, flagged words |

## About the dataset

`data/emails.csv` (≈770 labeled emails, roughly balanced spam/ham) is **procedurally generated** by `src/generate_data.py` from realistic templates — prize/lottery scams, phishing, fake account alerts, pharma/loan spam on one side; work emails, scheduling, receipts, and personal notes on the other. This keeps the repo dependency-free with no external dataset license to track, and the models generalize well to genuinely new spam/ham text (see the "Try an example" buttons, or test your own real emails).

**Swapping in a real-world dataset:** for a more rigorous benchmark, drop in the public [SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection) or [Enron-Spam](http://www2.aueb.gr/users/ion/data/enron-spam/) dataset — just reshape it to the same `label,text` CSV schema (labels `spam`/`ham`) and re-run `python src/train.py`. No code changes needed.

## How It Works

1. **Text → numbers**: `TfidfVectorizer` turns each email into a weighted vector of word/word-pair frequencies (unigrams + bigrams), down-weighting common English stop words and words that appear in almost every email.
2. **Naive Bayes**: learns `P(word | spam)` and `P(word | ham)` from the training set, then for a new email multiplies these probabilities together (via `MultinomialNB`) to decide which class is more likely.
3. **SVM**: `LinearSVC` finds the hyperplane in TF-IDF space that best separates spam from ham with the widest margin; `CalibratedClassifierCV` wraps it so its decision score can be read as a probability.
4. **Flagged words**: for whichever model is selected, the app ranks vocabulary by how strongly it favors the "spam" class and highlights any of those words present in your pasted message.
